**COMPASS CMP — review of refactor/frontend-architecture, completed 1 October 2026**

The refactor has established a useful foundation: separate staff and principal applications, feature-owned network access, server-owned permissions, immutable consent evidence, and substantive automated checks. The next investment should be correctness at trust boundaries, truthful workflow outcomes, and reliable delivery. Several important paths currently look successful without establishing the outcome they promise.

This review covers commit `861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3`. Both the local target branch and its remote were verified at that commit, including on 1 October. The checked-out branch is `sprint-3/breach-and-correction`; its subsequent changes are outside this assessment. An immutable archive of the target commit was used for checks. Code references below are pinned to the reviewed commit to avoid confusing newer work with these findings. Application source was not changed.

Five specialist sub-agents covered UX, security, DPDP, architecture, and scalability/integrations. The latter two initially hit a usage limit, then completed after the review resumed. Findings were consolidated and key paths independently inspected.

P1 means address before relying on the affected production workflow. P2 means a substantive improvement in the next hardening cycle. Readiness gaps and capacity risks are distinguished from demonstrated defects.

**Usability and UX**

**UX-1 · P1 · Whole-notice refusal cannot complete when a purpose is mandatory.** The [Decline everything action](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/portal/src/features/public-consent/components/notice-step.tsx#L76) sends every purpose as false. The [API validation](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/consent/service.py#L531) rejects every false mandatory grant. The UI explicitly recommends whole-notice refusal when the user does not agree, so this is a contradictory contract. Model complete refusal as a valid outcome and preserve its evidence; explain any consequent service limitation. Verify the complete mandatory-purpose refusal journey, not just button visibility.

**UX-2 · P1 · A failed disclosure request can tell a principal that data was never shared.** [Disclosures](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/portal/src/app/(app)/my-consents/page.tsx#L391) substitutes an empty array for missing data and shows “Not shared with anyone” once loading ends, without an error branch. Other evidence panels also hide failures. Display independent loading, error, empty, and success states with retry. Only assert absence after a successful response.

**UX-3 · P2 · Authentication recovery does not preserve progress.** After [successful OTP verification](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/portal/src/app/c/[token]/page.tsx#L163), a failed profile or notice fetch leaves the user on the code screen, although the code has been consumed. The verification component has no resend/change-contact controls. Separately, [sign-in](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/portal/src/app/sign-in/page.tsx#L137) suppresses operational request errors, while [link loading](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/portal/src/app/c/[token]/page.tsx#L76) treats outages as invalid links. Add a verified/loading-notice state with its own retry; distinguish neutral account-existence responses from transport failure, expiry, and rate limiting.

**UX-4 · P2 · Accessibility and localization need complete-journey coverage.** The [hidden consent radios](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/portal/src/features/public-consent/components/purpose-choice.tsx#L63) lack a visible enclosing focus indicator. Both mobile navigation drawers need focus transfer, containment, Escape dismissal, and restoration; reuse the accessible dialog primitive. Language selection arrives after identification and verification, key controls remain English, and translated content lacks appropriate language markup. Translate essential actions/errors, offer language selection earlier, and test the actual notice journey by keyboard and on narrow screens.

**UX-5 · P2 · List context is not retained through navigation.** [Filter state](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/console/src/components/data-display/resource-list.tsx#L366) is read from the URL at mount but subsequently kept locally; cursor history is also local. Refresh, sharing, and returning from details can lose the user's working context. Make filters and pagination URL-owned, with filter → detail → Back and reload tests.

**Security mechanisms**

**SEC-1 · P1 · The frontend decryption endpoint does not authenticate the session.** Both [console](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/console/src/app/dkms/decrypt/route.ts#L77) and [portal](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/portal/src/app/dkms/decrypt/route.ts#L77) check only that a cookie named `cmp_session` exists, then forward caller-supplied ciphertext to DKMS. Isolated tests of the actual handlers returned synthetic plaintext with a fabricated cookie and mocked upstream. This permits decryption of ciphertext an attacker already possesses; it does not independently provide database access. Move decryption into authenticated, resource-scoped server retrieval, or require short-lived capabilities bound to the session and authorized values. A valid-session check alone would still permit cross-scope ciphertext replay. Cover fabricated, expired, partial-MFA, revoked, and cross-scope requests.

**SEC-2 · P1 · Mobile formatting aliases bypass OTP issuance limits.** [Issuance throttles](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/auth/authentication/service.py#L235) use the lowercased input, but lookup canonicalizes telephone formatting. Four accepted formats were verified to map to one lookup identity and four quota identities. [Reissuance](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/auth/authentication/otp.py#L81) also resets the verification-attempt counter. Canonicalize once before throttling, lookup, and delivery; retain aggregate verification budgets across reissues and add network/device abuse limits. This closes repeated code invalidation and renewed guessing opportunities.

**SEC-3 · P2 · Failed authentication can lose its durable audit evidence.** [Login failure recording](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/auth/authentication/service.py#L76) occurs inside the [route transaction](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/api/routers/v1/auth.py#L140), followed by an exception that rolls back the insertion. MFA has the same structure. Redis lockout remains, but the recorded security event does not. Commit failure events through a dedicated security-event path or commit a decision before mapping it to an HTTP rejection. Add a database-backed test proving the event survives a failed request; wire authorization denial recording as well.

**SEC-4 · P2 · Close remaining enforcement gaps.** [Body-size enforcement](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/api/middleware/body_limit.py#L35) trusts Content-Length; an isolated streamed request exceeded the configured cap and was accepted. Count actual bytes at the ASGI boundary. [Consent submission](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/api/routers/public/consent.py#L252) bypasses the common CSRF dependency; default SameSite/CORS behavior mitigates exposure but does not replace the intended check. DKMS also lacks service authentication and permits HTTP transport: require authenticated TLS for cross-host production use and verify network isolation. Actual production exposure was not assessed.

**DPDP readiness**

As of 1 October 2026, most substantive fiduciary duties in the DPDP framework are still in the eighteen-month commencement group; Consent Manager registration is in the one-year group. These findings therefore describe implementation/readiness gaps, not a conclusion that already-effective substantive DPDP duties have been breached. The baseline is the [official commencement notification](https://www.meity.gov.in/static/uploads/2025/11/c56ceae6c383460ca69577428d36828b.pdf), [final Rules 2025](https://www.meity.gov.in/static/uploads/2025/11/53450e6e5dc0bfa85ebd78686cadad39.pdf), and [December 2025 corrigendum](https://www.meity.gov.in/static/uploads/2025/12/3c7ebbae0e5456f493f486e6845df86b.pdf).

**DPDP-1 · P1 · Returning a holder ticket is treated as successful execution.** [Ticket return](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/rights/service.py#L1087) accepts a nonempty summary and optional evidence; [erasure execution](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/rights/erasure.py#L182) treats RETURNED as done. [Correction completion](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/rights/execution.py#L115) likewise accepts return status without an explicit execution outcome. An isolated probe with a returned ticket saying “Unable to correct or erase data” and no evidence cleared the correction completion blocker. Add per-item executed/failed/partial/retained outcomes, accountable acknowledgements, and evidence or reviewed attestation. Failure must prevent a success claim. This is a practical gap in supporting correction/erasure rights under [section 12](https://www.meity.gov.in/static/uploads/2024/06/2bf1f0e9f04e6fb4f8fef35e82c42aa5.pdf).

**DPDP-2 · P1 · Withdrawal lacks tracked downstream action.** [Withdrawal](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/consent/service.py#L694) writes superseding grants, audits, and optionally emails the principal. It does not create processor cessation instructions, acknowledgements, or a retention/erasure assessment. CSV redistribution alone depends on manual follow-through. Persist a withdrawal event, derive affected recipients, deliver cessation instructions with retries/deadlines, and reconcile acknowledgements. Assess applicable retention grounds automatically instead of requiring a second request for every erasure consideration. Relevant provisions are [sections 6(6) and 8(7)](https://www.meity.gov.in/static/uploads/2024/06/2bf1f0e9f04e6fb4f8fef35e82c42aa5.pdf).

**DPDP-3 · P1 · Retention is not an operational lifecycle.** The [maintenance query](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/tasks/maintenance/retention.py#L83) checks consent validity rather than purpose retention/cessation; its erase branch only increments a counter. [Historical exports and response packages](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/rights/erasure.py#L21) are excluded from erasure without per-copy expiry or retention grounds. Build a store inventory and schedules for operational records, exports, attachments, response packages, logs, and backups. Track minimum retention, expiry, and legal holds explicitly; preserve necessary evidence without indefinitely exempting complete copies. Apply [section 8(7)](https://www.meity.gov.in/static/uploads/2024/06/2bf1f0e9f04e6fb4f8fef35e82c42aa5.pdf) together with the applicable retention requirements in [Rules 6 and 8](https://www.meity.gov.in/static/uploads/2025/11/53450e6e5dc0bfa85ebd78686cadad39.pdf).

**DPDP-4 · P1 readiness · Complete breach response beyond a register.** The reviewed commit has no implemented breach domain/router. Later Sprint 3 work is excluded and should be reviewed separately. The workflow needs awareness timestamps, affected-person discovery, notification content, delivery evidence, and escalation. Rule 7 distinguishes notification without delay from the detailed Board submission within 72 hours, subject to permitted extension. Build those separately rather than treating 72 hours as the deadline for every notification. [Final Rules, rule 7](https://www.meity.gov.in/static/uploads/2025/11/53450e6e5dc0bfa85ebd78686cadad39.pdf).

**DPDP-5 · P2 · Transfer assessment needs the actual recipient chain.** The [current gate](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/exchange/transfer.py#L9) assumes a site's processor is the recipient and checks its recorded country. [Export generation](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/exchange/service.py#L55) does not accept an explicit destination. Model intended recipients, processing locations, onward processors, and the policy version applied to each disclosure. Preserve the existing fail-closed unknown-country check; avoid presenting it as comprehensive transfer coverage. Relevant: [section 16](https://www.meity.gov.in/static/uploads/2024/06/2bf1f0e9f04e6fb4f8fef35e82c42aa5.pdf) and [rule 15](https://www.meity.gov.in/static/uploads/2025/11/53450e6e5dc0bfa85ebd78686cadad39.pdf).

The adult-only consent restriction is now enforced for known minors and unknown ages; older findings claiming direct minor consent are superseded. Guardian support is a future scope decision, including lawful guardians for relevant adults. A consent-management software product is not automatically a registered statutory Consent Manager; establish the intended role before applying that separate registration/interoperability workstream. Contracts, organizational procedures, legal retention grounds, and actual deployments remain outside repository verification.

**Coding architecture**

**ARCH-1 · P1 · Restore an executable CI gate.** The [active workflow](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/.github/workflows/ci.yml#L41) still names removed backend/frontend paths, uses the previous uv flow, and attempts to build a removed Dockerfile. A proposed replacement in documentation is not an active gate and still needs DKMS coverage. Update the actual workflow for all four projects, include isolated integration/security/HTTP suites, migration checks, generated-schema parity, and production builds, then make the resulting checks required. Local green tests cannot provide branch protection.

**ARCH-2 · P2 · API contract checks miss server field removal.** [Covers](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/console/src/types/api-contract.test-d.ts#L75) checks Local extends Generated. Extra local properties remain assignable when the server stops returning one. An in-memory compiler probe removed only `SourceOut.is_in_house` from the generated schema and produced zero diagnostics, despite [the stated regression guard](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/console/src/types/registry.ts#L101). Check consumed output keys and nullability in the appropriate direction, with explicit exceptions for intentional enum narrowing, or derive transport types and map them to view models. Add a negative contract test for removal. The contract test file does run; this is not a skipLibCheck issue.

**ARCH-3 · P2 · Mutation effects and cache invalidation disagree.** [Project approval](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/projects/service.py#L388) can publish a notice, but [the mutation](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/console/src/features/projects/mutations.ts#L74) invalidates project/dashboard keys without independent notice detail/list/copy-source keys. An isolated QueryClient probe confirmed those notice entries remain uninvalidated. Centralize invalidation by domain effect and test transitions with every affected view already cached. Do not rely on users refreshing or eventually refetching.

**ARCH-4 · P2 · Consolidate proven common code while retaining separate applications.** Of 138 common relative source paths, 90 files are byte-identical: 21 library, 15 component, 25 feature, eight type, five style files, and others. Extract stable UI primitives, transport/error handling, schemas, and contract types into workspace packages with explicit exports. Keep audience-specific flows, navigation, and policy consumers within their applications. This makes fixes to shared security and accessibility behavior land once.

**ARCH-5 · P2 · Enforce the documented application-service boundary.** [Registry routes](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/api/routers/v1/registry.py#L160) perform writes and audit recording directly, despite the documented service-only rule. Other routes contain SQL, and the rights service has grown to 3,123 lines. Extract use cases with shared transaction/audit ownership so HTTP, jobs, and future integrations call the same behavior. Add import-boundary checks; split by cohesive workflows rather than arbitrary file-size targets. A framework rewrite or microservice split is not justified by this review.

**ARCH-6 · P2 · Reject invalid production configuration early.** Both applications silently default their cross-portal URLs to localhost ([console configuration](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/console/src/lib/config/index.ts#L31), [portal configuration](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/portal/src/lib/config/index.ts#L31)). A deployment missing these settings can redirect users to their own computers. Validate production URLs explicitly and exercise both cross-portal navigation paths in deployment smoke checks.

**Scalability and external integrations**

**SCALE-1 · P1 · Post-commit side effects are not durable.** [Callbacks](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/core/after_commit.py#L59) are memory-only; [optional dispatch](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/tasks/dispatch.py#L94) logs broker errors and discards work. This includes [rights verification codes](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/rights/service.py#L336). A crash after database commit or a broker outage can lose the message required to proceed. Write an outbox record in the business transaction, deliver with bounded retries, record completion, and support replay. Verify crash/restart and duplicate-delivery behavior.

**SCALE-2 · P1 · SMS gateway failures do not match task retry policy.** The [HTTP adapter](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/infrastructure/sms/transport.py#L88) raises httpx exceptions or RuntimeError for non-success statuses. [Task autoretry](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/tasks/notifications/rights.py#L27) covers different exception classes. Transient timeouts and 429/503 responses therefore bypass retries, including authentication messages. Map retryable failures to a common transport exception, honor Retry-After where applicable, and expose permanent failures for investigation. Avoid blanket retries for invalid recipients or authorization failures.

**SCALE-3 · P1 · A rejected import row can still mutate a collection.** [Row ingestion](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/exchange/service.py#L710) upserts the collection before validating its consent reference. The [enclosing loop](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/domain/exchange/service.py#L659) catches validation/not-found failures without a row rollback, then the request commits. An invalid reference can therefore leave a new collection or altered count despite reporting rejection. Validate references before writes or use a savepoint per row. Add a database-backed test proving rejected rows leave no changes. This finding is based on transaction tracing, not a live database reproduction.

**SCALE-4 · P2 · DKMS fallback creates request amplification.** Both portals' [fallback path](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/console/src/lib/dkms/deep.ts#L146) handles most bulk errors with [unbounded Promise.all](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/frontend/console/src/lib/dkms/deep.ts#L181), one request per sealed field. A response with 600 fields can generate 601 attempts after a bulk failure, including throttling and several server/network failure classes. Use typed errors, retry individual values only for specific ciphertext validation failures, cap concurrency, and stop on transport/throttling errors.

**SCALE-5 · P2 · Multi-replica storage needs an implemented shared backend.** [Object storage](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/infrastructure/storage/object_store.py#L37) is a stub accepted at construction; failures arrive at save/read/delete time, and readiness omits storage. Local files require a shared durable volume across replicas. Implement and exercise the adapter or explicitly configure/test the shared-volume alternative. Reject unsupported storage configuration at startup and check availability in readiness.

**Capacity investigation.** The [audit chain](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/migrations/versions/0014_audit_chain_position.py#L50) intentionally serializes insertions with a global transaction-level advisory lock. Preserve its integrity guarantee. Measure lock waits, transaction duration, DKMS latency, queue age, memory during exports/imports, and end-to-end p95/p99 before redesigning it. No production throughput ceiling was measured in this review.

**Integration roadmap.** The [generic outbound client](https://github.com/pranaldongare/COMPASS_CMP/blob/861fe8f0dd1b5ec7bfeecb107c3f0e492490cba3/backend/api/src/cmp/infrastructure/external/clients.py#L31) has no current consumers. Before adding CRM, HRMS, ERP, research-system, or processor integrations, define service identities/scopes, versioned DTOs, operation idempotency, signed events, delivery/replay semantics, and reconciliation. Build the outbox and outcome acknowledgements first: withdrawal and rights execution already need them. Multi-tenant isolation is a separate product decision if several fiduciaries will share one deployment.

**What is working well**

Preserve the staff/principal separation; feature modules; central HTTP/error/query handling; server-derived navigation and transitions; scoped SQL and deny-by-default permissions; Argon2id and opaque sessions; MFA and atomic OTP consumption; immutable consent/notice evidence; fail-closed age handling; legal holds and erasure-attempt tracking; cross-border export checks; keyset pagination; correlated jobs; and current OpenAPI parity. These are meaningful improvements over earlier reviews.

**Recommended order**

1. Close the decryption authorization gap and OTP quota bypass; restore working CI.
2. Correct refusal, disclosure error states, rights execution outcomes, and import row atomicity.
3. Introduce durable delivery, repair SMS retries, and connect withdrawal to acknowledged downstream actions.
4. Finish breach response and enforce retention across every store with explicit legal grounds.
5. Fix cache invalidation/contracts, extract stable shared packages, complete accessibility/localization, and validate shared storage and measured capacity.

Each item should land with a regression that reproduces its failure mode. Reassess the newer Sprint 3 changes separately before carrying these findings forward as still open.
