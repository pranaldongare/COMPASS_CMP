# Every text (SMS) the application sends

[Every email](../email/email-list.md) · [Texts through Amazon SNS](../decisions/0043-texts-go-through-amazon-sns-from-the-workers.md)

Generated by `docs/tools/generate-message-lists.py` from the message catalogue
(`backend/api/src/cmp/core/messages.py`). Do not edit by hand; run the tool.

**27 texts.** Each is the short form of an email of the same name: a number gets the text, an address gets the email.

- **To**: one mobile number per text. A text is never copied.
- **Sender**: the gateway's sender ID (`SMS_SNS_SENDER_ID` or `SMS_HTTP_SENDER`). In India a sender ID works only after DLT registration.
- **Words**: the default below, until the office replaces them in the console under **Message templates**. At most 480 characters (three parts).
- **Length** is counted with the sample values the console preview uses; one part is 160 characters, then 153 each.

## Where texts stand, and the plan

### Already built

| Piece | State |
|---|---|
| One sending path, shared with email; a number gets the text | Built |
| Words edited by the office, with a length check | Built (console, Message templates) |
| Gateways: Amazon SNS (`SMS_TRANSPORT=sns`) or an HTTP gateway (`http`) | Built on branch `feature/sms-amazon-sns` |
| A test script, `backend/api/scripts/send_test_sms.py` | Built |
| Real delivery | Not switched on here: `SMS_TRANSPORT` is `console`, and this machine has no AWS credentials |

### To switch on texts (settings only, no code)

In `backend/api/.env`, with AWS credentials in the environment, then restart the API and the worker:

```
SMS_TRANSPORT=sns
SMS_SNS_REGION=ap-south-1
SMS_DEFAULT_COUNTRY_CODE=91
SMS_SNS_SENDER_ID=
```

A new AWS account starts in the SMS sandbox: texts reach only numbers verified in the AWS console, which is enough for a demo.
