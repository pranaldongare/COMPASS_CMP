# 4. The database

PostgreSQL, reached with psycopg 3 and hand-written SQL. There is no ORM
([ADR 0001](../decisions/0001-no-orm-raw-sql.md)). Paths are under
`backend/api/` unless they say otherwise.

## Where the schema lives

- `alembic.ini` points at `migrations/`; `migrations/env.py` takes the
  connection string from the application's own settings.
- `migrations/versions/0001_baseline_schema.py` … `0033_one_published_notice_per_project.py`
  are one linear chain. Revision ids are the bare numbers (`revision =
  "0019"`, `down_revision = "0018"`).
- There is no model metadata (`target_metadata = None`) - nothing is
  autogenerated. Every table, index, trigger and function is written by hand
  in SQL.
- Each migration runs and commits on its own (`transaction_per_migration`),
  so a failure rolls back only that revision.

### What a migration looks like

A long docstring saying *why*, SQL in module-level strings, and
`upgrade()`/`downgrade()` that execute them. This is
`0019_consent_scoped_request.py` in full:

```python
revision = "0019"
down_revision = "0018"
branch_labels = None
depends_on = None

UPGRADE = """
ALTER TABLE rights_request
  ADD COLUMN consent_id integer REFERENCES consent_artefact(consent_id);
CREATE INDEX rights_request_consent_idx
  ON rights_request (consent_id) WHERE consent_id IS NOT NULL;
"""

DOWNGRADE = """
DROP INDEX IF EXISTS rights_request_consent_idx;
ALTER TABLE rights_request DROP COLUMN IF EXISTS consent_id;
"""

def upgrade() -> None:
    op.execute(UPGRADE)

def downgrade() -> None:
    op.execute(DOWNGRADE)
```

A new table with its rules - `legal_hold`, from `0031_erasure_execution.py`:

```sql
CREATE TABLE legal_hold (
  hold_id          serial PRIMARY KEY,
  hold_uuid        uuid NOT NULL UNIQUE DEFAULT gen_random_uuid(),
  asset_id         int REFERENCES data_asset(asset_id),
  subject_user_id  int REFERENCES auth_user(id),
  reason           text NOT NULL,
  placed_by        int NOT NULL REFERENCES auth_user(id),
  placed_at        timestamptz NOT NULL DEFAULT now(),
  released_by      int REFERENCES auth_user(id),
  released_at      timestamptz,
  CONSTRAINT legal_hold_covers_one CHECK ((asset_id IS NULL) <> (subject_user_id IS NULL)),
  CONSTRAINT legal_hold_release_attributed CHECK ((released_at IS NULL) = (released_by IS NULL))
);
CREATE INDEX idx_legal_hold_asset ON legal_hold (asset_id) WHERE released_at IS NULL;
CREATE TRIGGER trg_legal_hold_release_only
  BEFORE UPDATE OR DELETE ON legal_hold
  FOR EACH ROW EXECUTE FUNCTION cmp_legal_hold_release_only();
```

**Downgrades are real.** Every migration has one, and CI runs up, down to
base, and up again. A downgrade refuses rather than deletes data: 0027 and
0028 cannot be undone once values are sealed, on purpose.

**Grants.** Some migrations revoke UPDATE and DELETE on evidence tables from
the application's database role (`CMP_DB_APP_ROLE`, default `cmp_app`). In
local development that role does not exist - you connect as the owner - so
those blocks do nothing and the triggers are the enforcement you will see.

## Conventions every table follows

- **Keys.** `<entity>_id serial PRIMARY KEY` for joins, and
  `<entity>_uuid uuid NOT NULL UNIQUE DEFAULT gen_random_uuid()` for the
  outside world. `auth_user` is the exception, with `id` and `uuid`.
  `audit_log.log_id` is the one `bigserial`.
- **Time** is `timestamptz`, and every connection runs in UTC. Stamps are
  named for the event - `placed_at`, `exported_at`, `received_at` - and
  `created_at` where nothing better fits. `updated_at` is maintained by the
  `cmp_touch_updated_at()` trigger on the tables that have it.
- **Enums** are PostgreSQL types (`CREATE TYPE … AS ENUM`), mirrored in
  `src/cmp/core/enums.py` and registered in `BY_PG_TYPE`; a test fails if
  the two drift. Newer tables sometimes use `varchar` with a `CHECK`.
- **Rules as named CHECKs** - `legal_hold_covers_one`,
  `rights_closed_has_outcome`, `*_attributed` (a timestamp and the person
  who set it come together), `*_indexed` (a sealed value always has its
  hash).
- **NOT NULL by default.** NULL means something specific: "not yet", or
  "nobody's" - a bystander in a recording has `asset_consent.consent_id`
  NULL.
- **Nothing is deleted.** Lifecycle is a status or a stamp - `deactivated`,
  `retired`, `revoked_at`, `released_at`, `lifted_at`. The few `DELETE`s in
  the code remove a draft notice's purposes, a draft project's processors, an
  office's wording override (back to the default), and a purpose an import
  created but never used.
- **Uniqueness that depends on state** is a partial unique index, e.g. one
  active restriction per country, one live nomination per person.

## What the database refuses

These rules hold whatever the code does. Each is a trigger, created in the
migration named:

| Rule | Tables | Migration |
|---|---|---|
| Append-only: no UPDATE or DELETE | `audit_log`, `consent_artefact`, `consent_purpose_grant`, `export_log`, `export_line`, `project_status_history`, `person_type_history`, `project_approval` | 0002 |
| Also append-only | `rights_ticket_message` / `rights_item_execution` | 0017 / 0031 |
| The audit hash chain, written on insert | `audit_log` | 0002, replaced in 0014 |
| A published notice, its text and its purposes are frozen | `notice`, `notice_language`, `notice_purpose` | 0002 |
| A consent must match its notice, language and link; a grant must be for a purpose on the notice | `consent_artefact`, `consent_purpose_grant` | 0002 |
| A link's site and notice must be one approved project; uses never exceed the cap | `consent_link` | 0002 |
| A data principal and a nominee must have a mobile | `auth_user`, `nomination` | 0015 |
| A contact belongs to one person | `auth_user` | 0025, rewritten 0028-0029 |
| A legal hold can only be released once; a restriction only lifted once | `legal_hold`, `restricted_country` | 0031, 0032 |
| One published notice per project (a partial unique index) | `notice` | 0033 |
| Project ownership follows its primary site and source (derives, does not refuse) | `project_site`, `data_source` | 0005-0008 |

Each rule is proven by a test in `tests/integration/enforcement/` that tries
to break it with raw SQL.

## Personal data in tables

- A sealed column is `text` holding an `SE::…` envelope.
- A lookup column has a partner `<column>_hash` (hex HMAC), with a `CHECK`
  that the hash is present whenever the value is and a unique index where
  the value must be unique.
- A searchable name has `<column>_ngrams text[]` with a GIN index.

The repository seals and indexes in the same statement -
`src/cmp/db/repositories/users.py` `create()`:

```python
sealed = await seal("auth_user", {"full_name": full_name, "email": email_n, ...})
row = await fetch_one(conn, """INSERT INTO auth_user (..., email_hash, mobile_hash, ...,
        full_name_ngrams) VALUES (...)""",
    (sealed["full_name"], sealed["email"], ...,
     index_of("email", email_n), index_of("mobile", mobile_n), ..., ngrams_of(full_name)))
```

Lookups compare hashes (`WHERE u.email_hash = %s`); name search uses
`u.full_name_ngrams @> %s`. `scripts/reseal.py` seals any value still in the
clear (`--check` reports without writing). The full procedure for a new
personal column is [adding a personal field](../dkms/adding-a-personal-field.md).

## The pool and transactions

`src/cmp/db/pool.py`:

- **The pool** holds 2-10 connections. Each new connection runs
  `SET statement_timeout = 15000; SET lock_timeout = 5000;
  SET idle_in_transaction_session_timeout = 30000; SET TIME ZONE 'UTC'` and
  returns rows as dicts.
- **`connection()`** is autocommit, for reads.
- **`transaction()`** is one transaction: commit on success, roll back on any
  exception, then run what was deferred to after commit. A database outage
  becomes a 503.

The router opens the transaction and hands `conn` down; services and
repositories never open their own. What must share one transaction - a
change and its audit row, an export and its lines, a transition and its side
effects - is listed in [transactions](../database/transactions.md). Sealing is
an HTTP call made inside the transaction: seal before the first audit write,
because the audit chain's lock is held until commit.

## Repositories

`src/cmp/db/repositories/` - thirteen modules of `async def fn(conn, ...)`
functions. Each takes a connection, runs SQL, returns dicts, and never opens a
connection. The helpers in `src/cmp/db/sql.py`:

- `fetch_one`, `fetch_all`, `fetch_val`, `execute`.
- `require_one` - a 404 when the row is absent *or out of scope*.
- `keyset_clause` - cursor paging.
- `as_conflict` - a constraint violation becomes a 409.

A typical function, `legal_holds.place()`:

```python
async def place(conn: Conn, *, asset_id: int | None, subject_user_id: int | None,
                reason: str, placed_by: int) -> Row:
    sealed = await seal("legal_hold", {"reason": reason})
    row = await fetch_one(
        conn,
        """INSERT INTO legal_hold (asset_id, subject_user_id, reason, placed_by)
           VALUES (%s, %s, %s, %s) RETURNING hold_id, hold_uuid""",
        (asset_id, subject_user_id, sealed["reason"], placed_by),
    )
    ...
```

Parameters are always bound (`%s` or `%(name)s`); only identifiers the code
itself validated - a sort column, a scope predicate - are placed in the SQL
text. Scoped reads splice the scope predicate into the WHERE clause:

```sql
WHERE p.project_uuid = %s AND (<scope predicate>)
```

## Seeds and resets

| Script (`backend/api/scripts/`) | Does |
|---|---|
| `seed.py` | The administrator (`admin@cmp.local`) and the reference configuration, directly in SQL; safe to re-run |
| `seed_demo.py` | After `seed.py`: ten and more of everything, through the API, as each role would make it; runs once per database |
| `reset_dev.py` | Drops and recreates the schema, migrates, seeds; asks you to type the database name |
| `db.py` | Read-only inspector: list tables, describe one, show recent rows, run a query in a rolled-back transaction |
| `reseal.py` | Seals any personal value still in the clear |
| `create_admin.py` | The first administrator of a real deployment |

`seed.py`, `seed_demo.py` and `reset_dev.py` refuse outside local/test; `reseal.py` refuses when encryption is switched off; `db.py` only reads.
